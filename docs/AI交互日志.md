## 一、批判性思维：发现并纠正 AI 错误

### 1.2 三个深度复盘

#### 复盘 A：成本数字算错 10 倍（09-01）

**交互过程**

> [AI] MiniMax speech-2.8-turbo 约 $60/百万字符，折算下来 0.4 元一万字，很便宜。
> [我] 手算：$60 / 1,000,000 字符 = $0.6/万字符，× 7.2 汇率 = **4.32 元/万字符**。你少算了一位小数点。
> [AI] 确认算错。

**影响**：这个数字直接决定技术选型。按错误值 MiniMax 比豆包便宜，按真实值它比豆包贵 44%、比阿里 CosyVoice v3.5-flash 贵 **5.4 倍**。

**纠正后的决策链**：MiniMax 设计费 ¥21.6/个 → 改用阿里 CosyVoice（**创建音色免费**）→ 加 `voice_design_cache` 跨用户缓存（同描述第二次不调接口、不扣费）→ 单次演示成本从 20+ 元压到接近零。

**沉淀规则**：**成本数字、单价换算、计费口径一律人工复核**。AI 在长数字串的单位换算上系统性不可靠。

#### 复盘 B：概率性失败的真根因（09-01，英文版）

**表面现象**：9 段《西游记》对话文本翻译，9 段全部 `en=None`，静默降级成中文。第一次修「分批」，结果变成 5 段成功 4 段失败——看起来像「模型不稳定」。

**我做的动作**：不接受「偶发」这个解释。临时加 `/debug/translate` 端点跑真实管线函数、逐批打印原始响应（用完即删），抓到实锤：

```
GLM 输出： "Sandy said, "Second brother...""
                        ↑ 字符串内未转义双引号 → json.loads 必炸
```

**为什么之前「时好时坏」**：重试依赖 GLM 碰巧改用单引号，概率性通过。对话密集文本几乎必踩。

**三层防御**：① PROMPT 强约束单引号风格 → ② 单批 JSON 两连败则绕开 JSON 逐段纯文本兜底 → ③ 单段输出长度校验防幻觉。失败段数写进任务 `note` 字段，前端可见。

**结果**：9/9 段纯英文，无降级，done 57.3s。

**沉淀规则**：凡是让 LLM 输出 JSON，且内容可能含引号，**必须备一条不经 JSON 的兜底路径**。

#### 复盘 C：能力边界识别 → 协作模式重构（08-29，故事内容）

这是全程**最有价值的一次边界判断**。

**尝试一**：GLM 批量生成 20 篇睡前故事（1300 字 + JSON 复合输出）。结果：**33 分钟只产出 1 篇达标**，其余 921 字不合格。

**尝试二**：改分步生成（先大纲后正文）——仍不稳定。

**用户叫停**：「别让它写了。」

**模式切换**：改为 **AI 在对话区直接撰写 → 我逐批审阅确认 → 落盘**。4 批完成 20 篇，质量达标，实测朗读时长 4:02~5:49（平均 4:47）。

**边界结论**：GLM-4-flash 能稳定输出**结构化标注**（分段 / 情绪 / 强度），但**写不了 1300 字的完整叙事长文**。前者短、可校验；后者长、失败率高且质量不可控。

**沉淀规则**：同一件事，AI 当「标注器」可靠，当「作者」不可靠。判断依据是**输出长度与可校验性**，不是任务听起来难不难。

## 二、批判性思维：多角度验证

### 2.1 三层验证体系

| 层级 | 手段 | 抓哪类问题 |
|---|---|---|
| **L1 接口级** | curl + 特征值 grep、PG 直查、API 级 E2E | 契约、鉴权、隔离（跨账号 401/404） |
| **L2 浏览器级** | Node 脚本 `require("playwright")` + `channel:"msedge"` headless 直驱 | DOM、状态机、跨页、真机视口 |
| **L3 目检** | playwright 截图（deviceScaleFactor=2）→ Read 工具逐张看 | 布局错位、配色、截断——**只有眼睛能发现** |

### 2.2 被验证环节坑出来的 6 条硬规则

| 规则 | 来源（踩坑实例） |
|---|---|
| **部署后必跑端到端，不看 `/health`** | GLM key 失效时 /health 全绿，但线上 /tasks 全部 401 |
| **灰度完成前的验证无效** | CloudRun 新版 FlowRatio=0 时请求跑在旧实例，E2E 首次误判 |
| **判断部署状态永远用 `getDeployRecords`** | `deploy` 返回的 buildId 是**上一次**的旧值，此坑复现 3 次 |
| **手工坐标排版必须截图目检** | 框架图 CSS position bug、P7 文字溢出画布，都是脚本查不出、眼睛一眼可见 |
| **持久化状态字段有「进程存活才有效」的语义** | `paused=false` 存档是陈旧值，页面 init 时不该信任，应按生命周期重新断言 |
| **注入测试数据前必须先冻结活页面** | 否则被 `ontimeupdate` 覆盖，误判成产品 bug |

### 2.3 两个低成本验证技巧

- **零成本验证「按次计费接口」**：先往缓存表预置一条记录（键 → 已知有效 ID），再用该键调接口。若返回值等于预置值，即证明真接口没被调用，不花一分钱验证了缓存读取路径。
- **不起服务校验后端路由**：managed venv 里 `import app` 即可确认路由注册与 provider 切换逻辑，无需拉起容器。

## 三、批判性思维：能力边界分析

### 3.1 分工边界（项目中实际执行的线）

| 交给 AI | 必须人工把关 |
|---|---|
| 结构化标注（分段 / 情绪 / 强度 / 角色） | **成本数字与单价换算** |
| 音色描述扩写（一句话 → 配音导演式 voice_prompt） | **接口契约与参数**（音色系别、JSON 字符串） |
| 代码实现、测试脚本、文档初稿 | **最终听感**——好不好听得戴耳机听 |
| 方案草稿、排版实现 | **伦理与合规判断** |

### 3.2 三条硬线（全程未破）

1. **故事正文禁止 AI 撰写** —— 全部改编自公版经典（伊索 / 格林 / 安徒生 / 西游记 / 神话），AI 只做标注与有声化，不做创作。
2. **不用盗版数据源** —— 用户提 wenku8.net 导书，**拒绝**：未授权盗版站，做抓取涉及侵权，答辩也答不住。改提供本地 TXT 导入 + 公版书库（ctext CC0 协议，13 部古籍）。
3. **不把 AI 输出当答案** —— 默认当草稿。错了容易看出来的（标注、扩写）可以交出去；错了不容易发现的（数字、契约、听感）必须自己过一遍。

### 3.3 边界被验证的具体时刻

- **MiniMax TTS 适合短句，不适合朗读** —— 用户实测「睡前故事姐姐」版「句子都念不全」，长句断句不稳 → 旁白回退豆包樱桃丸子，20 篇全部重渲。该音色留作备选，不再用于预渲染。
- **glm-4.7 不适合本场景** —— 非 flash 旗舰，长输出 JSON 延迟 9.3s/次（flash 720ms），端到端 300s 超时。
- **emoji→SVG 不能一刀切** —— 结构性 UI（导航 / tab / 按钮）全量换细线 SVG；但儿童夜间风的内容态 emoji（⏳ 状态行、随机封面）**保留**，那是产品个性不是 AI 感。

## 四、协作过程

### 4.1 四步闭环（全程执行）

```
我拆需求 + 定验收标准 → AI 出实现/草稿 → 我评审（实测，不看代码是否"看起来对"） → 迭代
```

分工明确：**边界和验收标准我定，实现细节 AI 写，但每一版必须实测**。

### 4.2 有效迭代轮次（主干，非全部）

| # | 事项 | 轮次 | 关键转折 |
|---|---|---|---|
| 1 | **技术路线** | 3 轮 | 本地 VoxCPM2 → **实测 RTF 18.4**（1 小时书要等 18 小时）→ 推翻，转纯云 API → 成本治理转双轨（CosyVoice 免费通道） |
| 2 | **故事内容生产** | 3 轮 | GLM 批量（33 分钟 1 篇）→ 分步（仍不稳）→ **用户叫停**，改对话区撰写 + 人工确认 |
| 3 | **迷你播放栏** | 5 轮 | 图标不切 → 播放键跳页 → 恢复时重播开场 → 初始态显示错误 → 恢复位置被覆盖；每轮都是**用户真机反馈**驱动 |
| 4 | **长文上限 5000→10000** | 2 轮 | 第一次「直接改数字」会挂（GLM 单次分析超时）→ 改为**分块分析** `analyze_long()`（1200 字/块 + 跨块角色统一） |
| 5 | **台词识别** | 3 轮 | 无引号对话（叠机械硬规则→改 prompt 语义判断）→ 混合句拆分（few-shot 补句式）→ 「」直角引号（正则扩展 + 说话人救援） |
| 6 | **英文版** | 3 轮 | 整篇降级 → 分批（9 段中 5 段）→ 抓真根因（JSON 双引号）+ 三层防御（9/9） |
| 7 | **生成按钮排版** | 2 轮 | AI 提 `clamp(100vh)` 全屏编辑器方案 → **用户否定**：「编辑器恢复原样，只调按钮」→ 改通栏按钮 |
| 8 | **架构框架图（本轮）** | 2 轮 | v1 双色语义三层九模块 → 用户给参考图 → v2 五段式（四色能力卡 + 知识链 + 强调卡 + 边界卡） |

### 4.4 协作中「人」不可替代的四个瞬间

1. **叫停内容生成**（08-29）—— AI 连试两种方案都不达标，是人判断「这条路不该继续走」，而不是继续调 prompt。
2. **否决全屏编辑器方案**（09-01）—— AI 解决了「有留白」这个表征，人指出真实诉求是「按钮不空」，不是「编辑器要变大」。
3. **真机截图发现播放栏被切**（09-01）—— 桌面模拟一切正常，只有真机能暴露 `env(safe-area-inset-bottom)` 问题。
4. **配色路线决策**（09-02）—— 借鉴参考 PPT 时，我先让用户选「融合 / 保守 / 照搬」，而不是直接重画 8 页。

## 五、答辩可直接用的话术

### 批判性思维（10 分）

> 我默认把 AI 的输出当草稿，不当答案。说三个真踩到的坑：
>
> 第一，**数字会算错十倍**——让它算 MiniMax 单价，它回「四毛钱一万字」，我一算是**四块三**。这个数直接决定选型，按错的算 MiniMax 最便宜，按对的算它比豆包贵四成、比 CosyVoice 贵五倍多。
>
> 第二，**会误判接口**——调 TTS 报错，AI 说是账号额度用尽。我换项目内置音色重测，全都正常。查文档才知道那个模型只认 2.0 系音色名，我挑的是 1.0 系——**不是账号，是参数**。报错信息完全看不出这个差别。
>
> 第三，**概率性失败背后有真根因**——英文版九段翻译全挂，AI 说重试就行。我不接受「偶发」这个解释，加了个调试端点抓原始响应，才看到它在 JSON 字符串里输出了**未转义的双引号**。
>
> 所以边界也就清楚了：结构化标注、文案扩写可以交给 AI，错了容易看出来；**成本数字、接口契约、最终听感必须人工把关**——好不好听 AI 说了不算，得我戴耳机听。还有硬线一条：**故事正文禁止 AI 写**，全用公版原文。

### 协作过程（10 分）

> 协作上我走四步闭环：我拆需求和验收标准，AI 出代码，我评审，再迭代。**边界和验收我定，实现细节 AI 写，但每版必须实测。**
>
> 最典型的一次是故事内容。AI 批量生成，三十三分钟只出来一篇合格的；改分步生成还是不稳。**我叫停了**——不是继续调 prompt，而是换模式：AI 在对话区直接写，我一批一批审，确认了才落盘。四批二十篇全部达标。
>
> 这让我看清一件事：**AI 当标注器可靠，当作者不可靠**。判断依据不是任务难不难，是**输出长度和可校验性**。
>
> 迭代三轮：第一轮跑通链路但粗糙；第二轮补移动端和离线下载，是**真机截图**发现播放栏被手势条切掉才改的；第三轮成本治理，换免费通道、上设计缓存。三轮的改进点，**没有一个是 AI 主动提的**。
