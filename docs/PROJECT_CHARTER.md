## 1. 项目概述

- **项目名称**：声卷（ShengJuan）—— 有声读物工作台 + 睡前故事播放器
- **定位**：产品化 Demo，「有声读物工作台 + 睡前故事播放器」双核心，聚焦亲子家庭；完整交互闭环 + 成品效果优先。（2026-08-31 调整，详见 PRD v2.0）
- **技术路线**：全云 API、本地零模型部署。
  - 情感分析：GLM-4-Flash（免费）+ 自动降级链
  - 语音合成：火山引擎豆包语音合成 2.0（主引擎）+ MiniMax（音色设计/备用）
  - 部署：腾讯云 CloudBase 云托管 + 静态托管 + PostgreSQL
- **核心差异化**：情绪曲线驱动、段落级增量重合成、智能多角色分饰、音色三合一（克隆/设计/方言）、生产与消费闭环（工作台成品经书架流转到睡前故事页）。
- **Demo 目标**：千字文本端到端 ≤ 3 分钟，全流程成本 ≤ 30 元。

## 2. 愿景与目标

让任何中文文本都能被“有情绪、有角色、有节奏”地讲出来。目标用户聚焦亲子家庭（2026-08-31 自四类收窄为一类）：

1. 家长（生产 + 管控）：用公版书/读本快速制作有声书，克隆「妈妈声/爸爸声」，方言祖辈音色讲老家故事；收听报告、每日上限、就寝时段管控。
2. 孩子（消费）：公版故事开箱即听 + 家长自制专属故事收听；断点续听、离线可听、夜间友好。

> 原内容创作者/视障银发/语言学习者三类人群的能力诉求与亲子场景高度重叠，Demo 阶段不再单独展开。

## 3. 核心原则

1. **合规优先**：文本来源必须公版/自有/授权；音色克隆仅限本人或已授权声音；成品需标识 AI 生成。
2. **成本可控**：优先使用免费额度与按需实例（`MinNum=0`），避免常驻实例烧光资源点。
3. **云端优先**：本地无 GPU，所有重计算走云 API；本地仅保留脚本、测试与构建。
4. **单文件前端**：前端页面保持单 HTML、无构建依赖，便于 CloudBase 静态托管直接部署。
5. **防御式部署**：每次部署后必须跑真实 `/tasks` 端到端，不能只看 `/health`；关键配置变更前小样本 probe。
6. **数据隔离**：账号级数据必须按 `uid` 隔离；后端使用 service_role 绕 RLS，但接口层必须校验 token。
7. **内容可维护**：故事/书库内容须来自公版经典，禁止原创杜撰；新内容上线前需人工确认。

## 5. 关键架构决策

1. **自建账号体系**：CloudBase Auth 不支持用户名密码自助注册，故自建 `users` 表 + PBKDF2 + HMAC token。
2. **音色库双轨**：旧 `user_voices`（每用户 1 条覆盖式，兼容保留）+ 新 `user_voice_library`（PK=(uid,voice_id)，命名/重命名/删除，登录多设备同步；重名检查由后端代码保证）。未登录用户走 localStorage 本地库，登录后自动迁移上云。
3. **内存态任务 + 单实例**：Demo 阶段任务状态保存在内存，云托管 `MaxNum=1`；生产化再外置共享存储。
4. **静态书库存量 JSON**：13 部公版古籍打包成 JSON 放 `web/lib/`，国内 CDN 直连，零第三方依赖。
5. **浏览器直连公版书源**：维基文库从国内云 DC 被墙，故主路线为浏览器直连（用户本地代理），云端接口仅作备用/诊断。
6. **GLM 降级链**：生产环境使用 `_glm_chat()` 自动轮询 `glm-4-flash → glm-4-flash-250414 → glm-4.5-air`，防止单 key/单模型失效导致服务全挂。

## 7. AI vibe coding 开发经验

> 本章记录项目开发过程中反复出现的同类错误、根因与规避方案。遇到相似场景时优先对照检查。

### 7.1 前端：单文件 HTML 中的常量时序（TDZ）

- **现象**：往 `<script>` 中段插入“启动即执行”的代码，引用了 `const $`、`const API`，触发 `ReferenceError`。
- **根因**：`const` 存在暂时性死区（Temporal Dead Zone），启动代码在常量声明前执行。
- **规避**：所有易碎常量（`$`、`API`、`BASE_URL` 等）统一放在 script 最顶部；新增启动代码前先确认其依赖的常量已声明。

### 7.2 前端：事件绑定选择器作用域污染

- **现象**：`我的音色` 删除按钮复用了 `voice-copy-btn` 类，导致 `renderVoices()` 里的全局 `querySelectorAll('.voice-copy-btn')` 把删除按钮的 `onclick` 覆盖成复制逻辑，点击删除无反应。
- **根因**：单页应用中批量绑定事件时选择器未限定作用域，且不同功能按钮复用同类名。
- **规避**：
  1. 选择器必须限定父容器，如 `#voiceList .voice-copy-btn`。
  2. 不同功能的按钮使用独立 class，不要图省事复用样式类。
  3. 新增 UI 后检查 `querySelectorAll` 是否误选。

### 7.3 前端：多弹窗关闭函数错绑

- **现象**：登录成功后调 `closeModal()`，实际关闭的是“自定义音色”弹窗，登录弹窗未关闭。
- **根因**：页面有多个 overlay/modal，新增弹窗时直接复用了旧关闭函数名。
- **规避**：每个弹窗使用独立关闭函数（如 `closeAuthModal()`、`closeVoiceModal()`）；新增弹窗时先确认关闭逻辑指向正确 overlay。

### 7.4 前端：localStorage 在沙箱/隐私模式下不可用

- **现象**：WorkBuddy 预览面板等 sandbox iframe 中 `localStorage` 访问抛出安全异常。
- **根因**：`document` 被 sandbox 且缺少 `allow-same-origin`。
- **规避**：封装 `store` 对象，启动时探测 `localStorage` 可用性；不可用降级为内存对象，避免全局崩溃。

### 7.5 后端：Flask CORS 头未放行 `Authorization` 与 PUT/DELETE

- **现象**：带 `Authorization` 的请求被预检拦截，或 PUT/DELETE 405。
- **根因**：`after_request` 中 `Allow-Headers` 未包含 `Authorization`，`Allow-Methods` 未包含 PUT/DELETE。
- **规避**：统一在 `after_request` 中返回完整 CORS 头，包含 `Authorization`、OPTIONS、PUT、DELETE、PATCH。

### 7.6 后端：环境变量 `EnvParams` 是全量覆盖而非补丁

- **现象**：`updateConfig` 只传部分 key 时，其余真实 key 被占位值（如 `keep`）冲掉，导致服务认证失败。
- **根因**：CloudBase `EnvParams` 每次更新都是整体替换。
- **规避**：每次修改 EnvParams 时必须携带全部环境变量；禁止只传“要改的那几个”。

### 7.7 后端：豆包 `additions` 必须是 JSON 字符串

- **现象**：方言参数 `additions` 传对象时返回 `55000000 反序列化错误`。
- **根因**：豆包 V3 接口要求 `additions` 字段是 JSON 字符串，而非嵌套对象。
- **规避**：构造请求前 `json.dumps(additions, ensure_ascii=False)`，接收方同理处理。

### 7.8 后端/前端：内存态任务在版本切换窗口 404

- **现象**：部署后 1–3 分钟内，新旧实例共存，提交的任务间歇 404。
- **根因**：任务状态存于内存，`FlowRatio` 切换期间请求可能打到没有该任务的新实例。
- **规避**：Demo 阶段 `MaxNum=1`；测试时等待版本切换完成；生产化外置共享存储。

### 7.9 后端：Glob 匹配范围过大

- **现象**：`s*.json` 同时匹配 `s01.json` 与 `s01.seg.json`，读取 seg.json 时 `KeyError: 'title'`。
- **根因**：通配符过于宽松，未区分故事文件与元数据文件。
- **规避**：精确匹配文件名模式，如 `s??.json` 或更严格的正则；新增文件类型时检查已有 glob。

### 7.10 后端：MiniMax 不需要 GroupId

- **现象**：MiniMax t2a_v2 拼接 `?GroupId=` 后返回 1004 token not match group，去掉后反而成功。
- **根因**：新版 API Key 与 GroupId 不绑定，传 GroupId 导致校验失败。
- **规避**：MiniMax 调用不再带 `GroupId`；如果以后切老 key，再单独 probe。

### 7.11 后端/模型：换模型前必须小样本 probe

- **现象**：直接切换 glm-5.3-flash 遇到 429/1214；glm-4.7 长输出 300s 超时。
- **根因**：coding plan 可用模型名与官方文档命名不一致；非 flash 旗舰长输出 JSON 极慢。
- **规避**：
  1. 任何模型切换先用短文本 probe（latency + 可用性 + 长输出耗时）。
  2. 生产链路必须带降级链，默认 flash 模型，非 flash 仅作备选。

### 7.12 后端：默认音色对长句朗读的质量差异

- **现象**：MiniMax“睡前故事姐姐”设计音色在故事长句/引号处断句不稳，句子念不全。
- **根因**：speech-2.8-turbo 对长叙事文本的断句不如豆包女声稳定。
- **规避**：故事朗读主音色固定使用豆包女声（樱桃丸子），MiniMax 音色仅作设计/短句备用。

### 7.13 部署：Git push 代理与 GCM 弹窗挂起

- **现象**：走 7897 代理推送时，Git Credential Manager 弹窗在非交互 shell 挂起，命令 27 分钟无输出。
- **根因**：GCM 在需要输入时无法弹出 GUI，等待超时。
- **规避**：使用 `GIT_TERMINAL_PROMPT=0 git -c http.proxy=http://127.0.0.1:7897 push`，禁用终端提示后走已缓存凭证。

### 7.14 部署：静态托管 CDN 缓存

- **现象**：上传新版 `index.html` 后浏览器仍显示旧版。
- **根因**：CloudBase 静态托管有 CDN 缓存，默认刷新非即时。
- **规避**：验证时加 `?v=N` cache-bust，或确认控制台 update 已全局生效。

### 7.15 前端：播放 keep-alive（微信/移动端熄屏）

- **现象**：手机熄屏或切后台后，音频约 1 分钟停止。
- **根因**：WebView/浏览器为省电会冻结后台音频进程。
- **规避**：多维度 keep-alive：
  1. 用 `userPaused` 标志区分用户暂停与系统自动暂停，自动暂停时尝试恢复。
  2. 后台播放静音 wav 循环占住媒体通道。
  3. `visibilitychange` 回前台续播。
  4. `WeixinJSBridgeReady` 放行 X5 媒体。
  5. `pagehide` 前保存进度。
  6. `MediaSession` 设置 `playbackState` 与 `stop` 行为。

### 7.16 内容：禁止凭空原创，必须公版/授权

- **现象**：初期尝试用 GLM 生成 20 篇儿童故事，质量不稳且存在原创杜撰风险。
- **根因**：GLM 长文+JSON 复合输出成功率低；AI 生成原创内容在答辩/商用场景下版权与合规风险高。
- **规避**：
  1. 故事内容必须改编自格林/安徒生/伊索/西游记/中国神话等公版经典。
  2. 长作品分集，并在文件中标明 `source` 与 `license`。
  3. 内容上线前人工确认，不直接由 GLM 批量写内容入库。

### 7.17 通用：API 响应字段变化

- **现象**：`/tasks/<id>` 默认不返回 `audio_base64`，前端 `atob(undefined)` 报错。
- **根因**：接口升级或默认参数变化，前端未同步。
- **规避**：后端接口变更时同步更新前端调用；拉取音频时显式加 `?audio=1`。

### 7.18 通用：部署后验证不能只看 health

- **现象**：GLM key 切换后 `/health` 正常，但真实 `/tasks` 全失败。
- **根因**：health 端点不跑实际 LLM/TTS 链路。
- **规避**：每次关键密钥或模型变更后，必须提交一个真实文本任务并检查完整输出。

### 7.19 测试：playwright-cli eval 的时序陷阱

- **现象**：用 eval 逐条断言短时序（如 4~7 秒的开场片段）时永远"错过窗口"，误判功能失效；`$()` 在 bash 双引号中被插值导致命令静默变形。
- **根因**：每次 playwright-cli 调用有 1~2s 延迟；`$`/反引号会被 shell 提前解释。
- **规避**：
  1. 点击与采样必须放进**同一个 eval**（页面内 setTimeout 定时采样）。
  2. eval 代码避免 `$()`、反引号，用 `document.getElementById`。
  3. 原型链 hook（`HTMLMediaElement.prototype.play`）必须先存 `__orig` 再覆盖，否则自递归会冻死页面。
  4. 本地 `python http.server` 不支持 Range 请求，seek 会触发媒体错误并被 keep-alive 自动恢复机制从 0 续播——验证 seek/断点行为要用支持 Range 的服务器或生产环境。

### 7.20 跨页面共享 localStorage：字段形状必须对齐

- **现象**：用户已在工作台登录，跳到睡前故事页（同域另一个 HTML）后，就寝门禁却判其"未登录"并弹登录引导。
- **根因**：工作台写入 `sqAuth` 的形状是 `{token, name}`，story.html 按想象的 `{token, username}` 读取——`auth.username` 恒为 undefined，登录检查恒判负。
- **规避**：
  1. 跨页面共享 localStorage 字段前，先 dump 一份真实数据确认形状，再写读取代码；不要按想象写字段名。
  2. 兼容历史数据时用双字段回退（`a.name || a.username`），story.html 共 4 处读取统一改造。
  3. 同理适用于所有共享 key：sqAuth、sqVoices、sqParentCtrl 等，建议在宪章或代码注释中登记权威字段清单。

### 7.21 暗底 UI 装饰素材：混合模式与可见度

- **现象**：夜云素材叠加到暗色 UI 上几乎不可见（透明度拉满也不明显）；工作台暖纸底上两枚暖色素材相邻则叠加显脏。
- **根因**：暗底必须用 `screen`/`lighten` 混合（`multiply` 会吃掉发光素材），而极暗素材（近纯黑）即使 screen + opacity 1 也只能轻微提亮；暖色系素材水平相邻时半透明叠加会互相污染。
- **规避**：
  1. 暗底 UI 素材提示词要求"主体亮度中等 + 背景与界面底色同族（如 #171522）"，叠加用 `screen`；亮底 UI 用 `multiply`。
  2. 一个区域只叠一张素材；装饰带落在有 max-width 的容器内时，mask 必须在容器边界前完全透明，否则出现硬切缝。
