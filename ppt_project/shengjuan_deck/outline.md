# 大纲：声卷 · 5 分钟汇报

## 风格：Swiss Grid（白底 / 黑字 / 瑞士红一处点缀 / 12 列网格）

---

### P1 — 项目一句话（对应逐字稿 P1，20 秒）
- 大标题：**把一段文字，变成一本能听的有声书**
- 副标题：声卷 · 个性化有声读物智能生成
- 底部一句（红）：它不是又一个 TTS 工具
- 支撑：普通合成整篇语气是平的，该紧张的地方不紧张
- 视觉：左侧粗竖线 + 大标题；右下角留白，仅一行红字

### P2 — 目标用户（对应 P2，20 秒）
- 标题：**只做亲子家庭**
- 左块 家长 / 白天：花几分钟把公版童话做成专属有声书
- 右块 孩子 / 晚上：打开手机就能听
- 底部小字：规划时画过四类人群，后来全砍了 —— 贪多，每个都做不深
- 视觉：两个等宽灰块（#F1F1F1），中间 24px 间距

### P3 — 技术栈（对应 P3，35 秒）
- 标题：**没独显，所以全走云 API**
- 因果条：本机没独显 → 实测本地 TTS 的 RTF 18.4 → 一小时有声书要等十八小时
- 四栏清单：GLM-4-Flash（免费，输出 JSON）/ 火山豆包 2.0（听懂情绪指令）/ CosyVoice（创建免费）/ CloudBase 云托管 + PostgreSQL
- 视觉：上方一条因果箭头（红），下方 4 个并排模块，数字标签 GLM / TTS / VOICE / BACKEND

### P4 — 亮点一：情绪曲线（对应 P4，30 秒）
- 标题：**拖哪一段，只重算那一段**
- 要点：大模型切段打标签（情绪 / 强度 / 角色）→ 前端画成能拖的曲线
- 关键数字：整篇重合成要等半分钟；增量重合成 —— 一秒出声
- 视觉：右侧一条可拖曲线示意折线 + 一个被高亮的圆点（唯一红色元素）

### P5 — 亮点二：音色三合一与成本（对应 P5，30 秒）
- 标题：**设计成本，压到接近零**
- 三合一：五秒录音克隆 / 一句话设计新音色 / 八种方言
- 成本对比条：MiniMax 一个音色 20+ 元 → CosyVoice 创建免费 + 设计缓存（同描述第二次直接复用）
- 视觉：两条横向条形（长灰=20+ 元，短红=接近零），下方三合一三个词

### P6 — 亮点三：跨页书架与移动端（对应 P6，25 秒）
- 标题：**工作台做的书，睡前故事页立刻能听**
- 要点：进度跨设备同步 / 音频一键下载 MP3
- 状态机：⤓ → 百分比 → ✓
- 移动端一行：底部播放栏被手势条切掉一半，加 safe-area 才解决 —— 真机截图才发现
- 视觉：左书架三个矩形块，右手机轮廓（直角矩形 + 底部红条标注 safe-area）

### P7 — AI 协作（对应 P7，2 分 20 秒，★两个评分点）
两栏布局：
- 左栏「AI 只干两件事」
  1. 情感分析：读全文输出分段 / 情绪 / 强度 / 重音词的 JSON
  2. 智能音色生成：一句话扩写成配音导演式描述
- 左栏下「我挑出的三个错」
  1. JSON 不合法：带引号对话塞进字符串，十次炸两三次 → 三层防御（强约束 / 整批重试 / 绕开 JSON 兜底）
  2. 数字算错十倍：它回「四毛钱一万字」，实际 4.32 元
  3. 误判接口：说是账号问题，实为 1.0 系音色不匹配 —— 不是账号，是参数
  - 结论（红）：AI 的输出我当草稿，不当答案
- 右栏「边界」
  - 可交 AI：结构化标注、文案扩写（错了容易看出来）
  - 必须人工：成本数字、接口契约、最终听感
  - 硬线：故事正文禁止 AI 写，全用公版原文
- 右栏下「四步闭环 + 三轮迭代」
  - 闭环：我拆需求与验收 → AI 出代码 → 我评审 → 再迭代
  - 分工：边界和验收我定 / 实现细节 AI 写 / 每版必须实测（十六条 Playwright 断言全绿）
  - 三轮：跑通链路（粗糙）→ 补移动端与下载（真机截图发现）→ 成本治理（换免费通道、上缓存）
  - 落点：三轮改进点，没有一个是 AI 主动提的

### P8 — 收尾（对应 P8，10 秒）
- 主句（大号）：**判断对错，AI 完整地留给了我**
- 副句：它把写代码的时间省下来了
- 红色落点：而后者，才是这个项目真正的工程量
- 视觉：居中大句 + 左下角项目名，其余留白

---

## 内容纪律
- 每页标题 ≤ 20 字，要点 ≤ 30 字
- 数据优先，形容词能删就删
- 保留口语原话，不改写为书面套话
- 不凑三点：P1/P2/P8 单点，P5 两点对比，P7 因评分需要密度高但保持分栏
