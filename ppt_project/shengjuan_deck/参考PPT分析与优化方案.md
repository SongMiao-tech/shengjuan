## 一、参考 PPT 值得借鉴的 8 个要点

### 1. 结构：8 页一条完整叙事弧线，每页功能不可替代

封面（是什么）→ 用户（为谁）→ 技术（怎么实现）→ 亮点一/二/三 → AI 协作（怎么跟 AI 合作）→ 结尾（收获）。

没有"过渡页""目录页""总结页"这类占位页，1 页 ≈ 35 秒，密度均匀。

### 2. 内容组织：标题即论点，不是名词标签

| 参考的标题 | 类型 |
|---|---|
| 目标用户收得很窄：亲子家庭 | 判断 + 理由 |
| 技术路线是被硬件逼出来的 | 因果判断 |
| 亮点一 · 情绪曲线编辑器：拖一下，一秒出声 | 卖点 + 利益点 |
| AI 协作：用在哪、错在哪、怎么合作 | 三个角度预告 |

观众只扫标题，就能把 8 页连成一条完整的论证链。这是这份 PPT 最大的优点。

### 3. 页内二次分节，形成四级信息层次

每页内部用 11pt 强调色小标签再切块：

- S4：`怎么做到的` / `真正的难点`
- S5：`三种获取音色的方式` / `一笔真实成本账`
- S6：`跨页书架` / `移动端踩的坑`
- S7：`AI 只干两件事` / `三个真踩到的坑` / `能力边界` / `四步闭环` / `三轮迭代`

层次链：**页标题（论点）> 分节标签（角度）> 正文（论据）> 句内高亮（关键词）**。四级清晰，扫读友好。

### 4. 母版网格极度稳定，翻页时元素"跳"得少

- 左右各留白 `1.11in`（≈107px），内容宽 `11.11in`，全篇不动
- 页标题 `y=0.69in`，下方一条 `1.11in` 宽的强调色短线（3pt）——**与左边距同宽**，形成对齐关系
- 块与块之间用 1pt 浅灰分隔线（`#C8D2CD` / `#D2DAD5`）而不是靠留白
- 内容底部统一收到 `y≈6.4in`，底部留白稳定

### 5. 配色：语义化双色系统（最值得借鉴的一点）

不是"一个强调色走天下"，而是**给颜色分配语义**：

| 颜色 | 色值 | 语义 |
|---|---|---|
| 墨绿 | `#4C7A5A` | 解法 / 正面 / 结论 / 分节标签 / 箭头 |
| 赭石 | `#8C5A46` | 问题 / 代价 / 错误 |
| 深墨 | `#2E3238` | 主文字 |
| 中灰 | `#4A5568` | 副文字 |
| 浅灰 | `#78827D` | 注释 |
| 页底 | `#F4F6F5` | 背景（非纯白） |
| 浅绿卡 | `#E0EBE4` / `#E8EEEA` | 解法块、结论块 |
| 浅赭卡 | `#EBE4E1` | 问题块 |

观众扫一眼颜色就知道"这块在说问题还是解法"，**不需要先读文字**。

### 6. 图表/图形：数字大字化 + 问题→解法对照卡

- 关键数字脱离正文单独放大：`RTF 18.4` → **72pt**；`20 多元/个` 与 `接近零` → **36pt**
- 流程用 `①②③` + 细箭头**横向**串起来，不做纵向堆叠
- 成本账是 `原本 → 换方案 → 实际` 三段递进，箭头连接，形成推导链
- 问题框（浅赭）→ 箭头 → 解法框（浅绿），构成左右视觉对照

### 7. 信息层次：句内加粗高亮

长句里只给 **1 个**关键词加粗 + 上色，其余保持常规字重：

- 「整篇重合成要等**半分钟**」（赭）
- 「睡前故事页**立刻能听**」（绿）
- 「底部播放栏被全面屏手势条**切掉一半**」（赭）
- 「**16 条 Playwright 断言全绿**才敢发」（绿）

视线有落点：先抓住关键词，再读全句。

### 8. 字号跨度 6.5 倍，层级一眼可辨

`11pt`（分节标签）→ `12pt`（小标签）→ `15–16pt`（正文）→ `22pt`（副标题）→ `28–30pt`（页标题）→ `36pt`（关键数字）→ `72pt`（封面大标题 / 核心指标）

| 页 | 我的现状 | 参考的做法 | 差距与改进理由 |
|---|---|---|---|
| **P1 封面** | 大标题两行 64px「把一段文字，变成／一本能听的有声书」；左上英文标签 `SHENGJUAN · 课程演示` | 巨字「声卷」**72pt** 作主视觉 + 副标题一句 + 竖色条 + 定位句 | **封面上根本没有项目名大字**。观众第一眼应该看到「声卷」两个字并形成记忆点，现在是读完两行副标题才知道这是什么项目。 |

| **P6 亮点三** | 三张错落书架卡 + 手机轮廓 + 红色 safe-area 条 | 左：三条特性（分隔线分隔）；右：问题卡（浅赭）→ 解法卡（浅绿） | 书架卡占了半页面积但信息量低（书名 + 状态）；**移动端那个真机坑被挤到右下角 3 行小字**。参考把「问题/解法」作为右半页主体，故事性更强。 |
| **P7 AI 协作** | 左右两栏，左「两件事 + 三个错 + 结论」，右「边界 + 四步闭环 + 三轮迭代」 | 同构，但右栏用 11pt 分节标签切成 3 个独立块 | **硬伤：内容溢出画布**。末行 `y=714/720`，转 PPTX 后文本框落到 `7.51in > 7.5in`。且右栏 5 个分节标签一个都没有，块与块只靠留白区分，扫读困难。 |

## 三、跨页共性问题

1. **配色无语义** —— 只有一个红 `#E63946` 当万能强调色，无法区分「问题」与「解法」。
2. **背景纯白 `#FFFFFF`** —— 投影仪上易过曝；参考用 `#F4F6F5` 浅灰绿，柔和且不刺眼。
3. **英文小标签** —— `USER` / `STACK` / `HIGHLIGHT 01` / `AI COLLABORATION`，与中文正文割裂。
4. **无句内高亮** —— 整块文本一个颜色一个字重，视线没有落点。
5. **字号层级偏平** —— 主体集中在 16–20pt，缺少 36pt 以上的数字锚点。
6. **⚠️ 字体写入 bug（实测确认）** —— SVG 里 `font-family="微软雅黑, Arial, sans-serif"` 被**整串当作单一 latin typeface** 写入 PPTX，且 `a:ea`（东亚字体）**未设置**：

   ```
   '只做亲子家庭'  latin= 微软雅黑, Arial, sans-serif   ea= None
   ```

   PowerPoint 会把「微软雅黑, Arial, sans-serif」当成一个不存在的字体名，中文实际回退到默认字体（等线/宋体），**微软雅黑全程没生效**。

## 四、优化方案（借鉴点落地清单）

| # | 借鉴点 | 落地做法 |
|---|---|---|
| 1 | 语义化配色 | 建立双色系统：墨绿 = 解法/正面/结论，赭石 = 问题/代价/错误 |
| 2 | 稳定母版 | 左右各留白 107px，内容宽 1067px；页标题 `y=66`，下挂 107px 强调线 |
| 3 | 页内分节 | 每页用 11pt 强调色中文小标签切块，块间 1pt 分隔线 |
| 4 | 标题即论点 | 8 个标题全部改成带判断的陈述句 |
| 5 | 句内高亮 | 每处长句给 1 个关键词加粗 + 强调色 |
| 6 | 数字大字化 | `RTF 18.4` 提到 72pt 级；成本数字 36pt 级 |
| 7 | 问题/解法对照 | 浅赭卡（问题）→ 箭头 → 浅绿卡（解法） |
| 8 | 流程横排 | `①②③` + 细箭头横向串联，不做纵向堆叠 |
| 9 | 修字体 bug | `font-family` 按逗号取首项，同时写入 `a:latin` 与 `a:ea` |
| 10 | 修 P7 溢出 | 压缩文案 + 收紧行距，全部内容收进 `y ≤ 690`，保持单页 |

**保持不变**：8 页结构、逐字稿全部事实与数据、逐页核心论点、纯矢量可编辑（0 图片）。
